# Submitted PR: Keep the final Yahoo quote for each daily date

Status: submitted as [FinanceDataReader PR #291](https://github.com/FinanceData/FinanceDataReader/pull/291) on 2026-10-02; maintainer review and merge are pending.

Fixes #272.

Yahoo's daily chart response can contain two rows for the same date, including an appended updated quote. Normalizing the timestamps currently leaves both rows in the returned daily DataFrame. When a multi-symbol request combines that index with a different symbol's dates, pandas can raise `InvalidIndexError`.

Keep the final complete Yahoo row for each normalized date before returning the data or aligning multiple symbols. This preserves the final row's OHLC, volume, and adjusted close together. The same daily-row choice is used in [yfinance's Yahoo response handling](https://github.com/ranaroussi/yfinance/blob/5cae563642b59f49adf6a04a5ad6744f8b0e084d/yfinance/utils.py#L705-L711).

The offline regressions use Yahoo-shaped JSON responses and the differing Nasdaq values reported in #272. They cover distinct and identical raw timestamps for a duplicate day, single-symbol output, multi-symbol alignment, unchanged unique dates, and existing request-period boundaries including a single-day request.

Validation on Linux, Python 3.12 and pandas 3.0.6:

- Unchanged source: four regressions fail; the unique-date control passes. The multi-symbol regression reproduces `InvalidIndexError`.
- Patched source: `python -m pytest tests/test_yahoo_duplicate_dates.py -q -W error --tb=short` → 5 passed.
- `git diff --check` passes.

Today's live Yahoo responses did not contain duplicate dates; the reported behavior was reproduced using deterministic API-shaped fixtures. The existing tests that depend on live market services were not run.
